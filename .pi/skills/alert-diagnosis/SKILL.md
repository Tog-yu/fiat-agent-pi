# 告警诊断（alert-diagnosis）

只读工作流：收集证据 → 对照知识库 → 给出根因假设与处置建议。全程不写生产数据。

## 铁律
- 只用只读工具：`fiat_es_search_logs`（日志）、`fiat_db_query`（业务库只读）、`mcp_rag_*`（知识库）。
- 不改数据、不提交、不自动执行任何写操作。需要写时，先给出工单建议交人工审批（见 P5）。
- LLM 不参与金额计算与状态机判断；只做证据归纳与假设排序。

## 流程
1. **澄清范围**：从告警文本提取关键维度（服务/时间窗/错误码/用户量）。若缺失且无法从上下文推断，向用户确认，不要臆测。
2. **收集证据**（并行调用只读工具）：
   - `fiat_es_search_logs`：按服务+时间窗拉 error/warn 日志，统计错误码 TOP。
   - `fiat_db_query`：必要时查相关表（如 `orders` 状态分布），`where` 只写只读条件。
   - `mcp_rag_query_knowledge_hub`：检索历史同类故障的复盘/runbook。
3. **归纳**：把证据列成「现象 → 证据 → 可能根因」三栏，按似然排序。
4. **处置建议**：给出可操作的下一步（如重启某服务、扩某队列、回滚某发布），标注风险等级。
5. **通知（可选）**：若已确认需协同，用 `fiat_lark_send` 把结论摘要发到值班群 —— 非破坏性，但仍需 oncall/ops 角色。

## 输出格式
```
## 告警摘要
<一句话>

## 证据
- 日志：<错误码 TOP / 时间分布>
- 业务库：<相关表状态分布>
- 知识库：<命中的 runbook/复盘>

## 根因假设（按似然）
1. <假设> —— 支撑证据
2. ...

## 建议处置
- <动作>（风险：<Lx>）
```

## 边界
- 证据不足时明确说「无法定责」，给出补充采集建议，不要硬给结论。
- 涉及 `cashback_*` / `logistics_*` 的写操作一律引导到 dry-run（P4）再走审批（P5）。
